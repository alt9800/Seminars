3D Tiles：位置を持った3Dデータの配り方

3D Tiles は、大量の3Dデータを地図タイルのように分割し、見えている範囲・距離に応じて必要な分だけ読み込むための形式です。中身の一つ一つは glTF（GLBの仲間）で、全体の目次として tileset.json があります。

GLBと違い、地球上の位置と、遠くでは粗く近くでは細かく見せる詳細度の切り替えをデータ自体が持っています。

建物をクリックすると「地面に合わせる」が使えます。

建物をクリックすると、その建物が持つ属性を表示します。

このページは地形を読み込んでいないため、地面は「楕円体（高さ0）」の位置にあります。一方でPLATEAUの3D Tilesの形は楕円体高で作られているので、建物は地面から浮いて見えます。浮いている分が、おおよそ「標高＋ジオイド高」です。次のタブで地面を点として足してみます。
確かめてみよう：属性の _zmin・_zmax は標高（ジオイドが基準）の値です。青山付近で建物の屋根の位置を実際に測ると、_zmax より約36m高く出ます。この差がジオイド高です。
コード：3D Tilesを読み込む 
const tileset = await Cesium.Cesium3DTileset
  .fromUrl('https://.../tileset.json');
viewer.scene.primitives.add(tileset);

// クリックした建物の属性を読む
handler.setInputAction((e) => {
  const f = viewer.scene.pick(e.position);
  if (f instanceof Cesium.Cesium3DTileFeature) {
    for (const id of f.getPropertyIds()) {
      console.log(id, f.getProperty(id));
    }
  }
}, Cesium.ScreenSpaceEventType.LEFT_CLICK);

DEMの格子を「点」として置く

一章で見たDEMは、決まった間隔に並んだ点の高さの集まりでした。ここでは国土地理院の標高タイル（標高PNG）を読み、格子の1マスを1つの点として、その高さに置きます。

色は標高で塗り分け
低高
「ジオイド高を足す」を外すと、点は建物の足元より下に沈みます。標高（ジオイドが基準）と楕円体高（楕円体が基準）の差が、そのまま見た目のずれになることを確かめてください。ジオイド高 36.0 m は、青山付近でPLATEAUの屋根の高さと属性 _zmax の差から求めた概算値です。正確な値は国土地理院のジオイド高計算で確認できます。
コード：標高PNGから点を作る 
// 標高PNGの1画素 → 標高（m）
function decode(r, g, b) {
  const x = r * 65536 + g * 256 + b;
  if (x === 8388608) return null;          // 2^23 は欠損
  return x < 8388608 ? x * 0.01 : (x - 16777216) * 0.01;
}

const points = viewer.scene.primitives
  .add(new Cesium.PointPrimitiveCollection());
points.add({

  color: Cesium.Color.fromHsl(hue, 0.6, 0.5),
  pixelSize: 3
});

点群：格子に並んでいない高さ

前のタブの点は、DEMの格子に沿って規則正しく並んでいました。航空レーザ測量や地上のレーザスキャナで得られる点群は、レーザが当たった場所ごとに点があり、間隔はばらばらです。木の枝や電線、建物の壁など、地面以外にも点があります。

DEMは、この点群から地面に当たった点だけを選び、格子に並べ直して作られます。つまり点群は、DEMになる前の、より生に近い高さのデータです。

Gaussian Splatting：見た目まで含めた点

写真から3次元の場面を復元する手法の一つです。点の代わりに、色・透明度・広がり（楕円体の形と向き）を持った小さなぼかしの粒を大量に置き、重ねて描くことで写真に近い見た目を作ります。

2026年には、Splat を glTF に格納する拡張（KHR_gaussian_splatting）が Khronos Group で策定され、3D Tiles に載せて地図上に配信する仕組みも整いつつあります。
